# ChatWorkBridge

在 Windows 上把 **ChatGPT 网页聊天**与 **WorkBuddy 桌面版**连接起来：GPT 派工，WorkBuddy 执行，再把结果送回原 GPT 聊天审核、返工与验收。

这是实验性项目。使用自己的应用安装和账号，不附带浏览器、WorkBuddy、模型或登录凭据，也不提供模型服务。

```text
ChatGPT 网页 → 本地桥接 → WorkBuddy 桌面
     ↑                     ↓
     └──── 执行结果与附件 ────┘
```

## 准备与安装

- Windows、Node.js 22.13 或更新版本、已安装的 Chrome 和 WorkBuddy 国际版。
- 使用自己有权使用的账号，首次启动后在两个窗口中自行登录。
- 当前启动器保留 E 盘存储检查。请把项目放在 E 盘；程序位置通过本地配置填写，例如 `E:/Apps/WorkBuddy/WorkBuddyAI.exe`。

```powershell
npm ci
Copy-Item config/local.example.json config/local.json
```

编辑 `config/local.json`，填写本机程序与资料目录。这个文件不会提交到 Git。依赖发生变更时使用 `npm install` 更新安装；日常按锁文件使用 `npm ci`。

启动、授权与运行入口见 [本机安装说明](docs/SETUP.md)。配置示例见 [local.example.json](config/local.example.json)。不要把账号资料目录或授权记录提交到仓库。

## 可以做什么

- GPT 与 WorkBuddy 自动往返，支持派工、返工、最终验收及有限执行轮数。
- 同一任务复用同一个 GPT 聊天；新任务复用受管标签页，旧聊天保留在历史中。
- SQLite 保存任务、发送记录与状态；遇到结果不确定时停止，避免盲目重做。
- 本地操作界面支持开始任务、当前回复结束后暂停、继续正常暂停的任务。
- 将可实际取得的图片和文件传给 WorkBuddy；附件按消息绑定、大小和文件头检查。

开发环境已验证文字闭环，以及专用测试中的文件创建和修改、固定 Node 命令、Chrome 本地页面操作。TXT、PNG 的读取和转发也完成了真实测试。**这些测试不代表任意软件、文件格式或用户工程均已验收。** 详细边界见 [功能状态](docs/STATUS.md)。

## 日常 WorkBuddy 与测试配置

测试模式使用独立资料目录，因此不含你日常配置的 MCP、Skill 和会话。

正常模式启动器可在本机明确授权后直接使用现有 WorkBuddy 资料目录，沿用现有 MCP、Skill 和普通权限，不复制凭据，也不添加绕过权限检查的选项。请先保存工作并退出既有实例；启动器不会主动终止日常会话。

**正常模式首次完整接入仍待验证。** 当前仓库提供的是接入实现和配置流程，不能把准备好的启动器视为任意电脑上的成功验收。工作器执行权限由所用 WorkBuddy 配置决定；本项目没有完成 Windows 系统级沙箱。

## 模型规则

默认自主调用白名单仅包含：

- `hy3`
- `step-5-preview`
- `deepseek-v4.1-flash`（支持别名 `deepseek-4.1flash`）

这是本项目使用者指定的免费模型策略，**不是提供方价格、余额或永久免费的保证**。其他模型及自动模型别名默认拦截，需使用者另外批准后才能启用。

DeepSeek 与 HY3 已实际成功。Step 的一次测试返回服务端 500，尚未通过实际执行验收。剩余额度、额度重置时间未知。

已实现明确额度耗尽、短时限流、服务错误的分类与获准模型切换；额度耗尽场景目前只通过模拟注入测试，尚未遇到真实额度耗尽。发生工具执行、已有正文或无法确认是否执行时，会停止而不是自动换模型重做。

## 限制

- 依赖 ChatGPT 网页结构及 WorkBuddy 桌面的本地通信协议，应用更新可能导致适配失败；这不是官方 ChatGPT API 或 WorkBuddy 插件。
- 当前任务入口和完整正常模式的开放程度见状态文档；专用能力测试成功不等于通用文件任务已开放。
- 只有文件名、没有可下载链接且没有已知本地原文件的附件卡片暂不能自动取回。PDF、Word 尚未逐种实测解析。
- 暂停恢复已测试；结果不确定的任务仍需人工核验，没有自动保证所有异常都能恢复。
- 本地桥接按配置重定向自己的日志和运行数据。应用自身可能产生系统运行记录，不能把目录重定向视为系统级写入隔离。
